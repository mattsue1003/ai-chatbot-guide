    卡住了？常見問題

    傳訊息給機器人，完全沒反應
    • Apps Script 部署時「具有存取權的使用者」必須是 所有人，不是「擁有 Google 帳戶的使用者」。
    • 網址要用結尾是 /exec 的那一個，不是 /dev。
    • 改過程式碼後要「管理部署作業 → 編輯 → 版本選『新版本』→ 部署」，否則網址還在跑舊的程式。
    • LINE：確認「Use webhook」已開啟，且官方帳號的「回應設定」裡 Webhook 是開的。
    想要回覆更快：把中繼站換成 Cloudflare Workers
    • Apps Script 每則訊息都要先啟動，大約多等 1～3 秒，而且模型忙線時沒辦法設定「等太久就換一個」。這是平台本身的限制，改程式碼省不了多少。
    • 頁面上方把中繼站切到 Workers（較快），步驟會換成 Cloudflare Workers 版：啟動幾乎不用等、模型 8 秒沒回應就自動換下一個。
    • Telegram 版還會「邊寫邊顯示」：AI 寫出前幾個字就先送出，再持續更新同一則訊息。LINE 不能修改已送出的訊息，所以只會省掉啟動時間。
    • 已經用 Apps Script 做好的機器人要搬過去：Gemini 金鑰和平台權杖都不用重新申請，只要做「建立 Worker」「貼程式碼」，再把 Webhook 網址換成 Worker 的網址。
    Workers 版：傳訊息沒反應
    • 用瀏覽器打開「你的 Worker 網址?test=1」，它會一次檢查四件事，哪一行是 ✗ 就修哪一行：Gemini 金鑰、平台權杖、平台上登記的 Webhook 網址是不是這個 Worker、（LINE）Use webhook 開關。
    • 最常見：LINE Developers 的 Webhook URL 還是舊的 Apps Script 網址，或填成 Telegram 那個 Worker 的網址。LINE 和 Telegram 要各建一個 Worker。
    • 第二常見：複製程式碼時 LINE 權杖那一格是空的，程式碼裡還是「在這裡貼上…」的中文提示。回到小工具填好兩把鑰匙，重新複製、貼上、按 Deploy。
    • 四行都是 ✓ 還是沒反應：在 Cloudflare 的 Worker 頁面開 Logs（記錄），傳一則訊息，看有沒有出現「LINE message/reply 失敗」之類的訊息。
    出現「402 Your prepayment credits are depleted」
    • 意思是：這把 Gemini 金鑰所屬的專案開了付費（預付制），但儲值金是 0。這時連到同一個帳單帳戶的所有金鑰都會一起停用，Google 不會自動幫你改回免費方案。
    • 想繼續免費使用：到 AI Studio 的 Projects 頁建立一個新專案，確認它的 Billing Tier 欄顯示 Set up billing（代表沒有綁帳單，不要點進去設定付費），再到 API 金鑰頁按 Create API key、選這個新專案。
    • 把新金鑰換到程式碼的 GEMINI_API_KEY，Apps Script 要「部署新版本」，Workers 要再按一次 Deploy。
    • 想付費使用：到 AI Studio 的 Billing 頁按 Buy credits 儲值（最低 5 美元，12 個月後過期、不能退款）。
    • 預防：申請金鑰時，畫面如果請你「Set up billing」或填信用卡，請直接略過，免費方案不需要。
    機器人回覆很慢
    • 正常速度：短問題大約 2～5 秒。每次都超過 10 秒，通常是模型的關係。
    • 最常見的原因是用了會先「思考」再回答的模型（例如 gemini-3.8-flash）。聊天機器人請在程式碼小工具選 快速（建議），用 lite 模型。
    • 想知道時間花在哪：在 Apps Script 的函式選單選 speedTest 按執行，執行記錄會列出每個模型各花幾秒，把最快的那個填到 MODEL。
    • 隔一陣子沒用，第一則訊息會多等 1～3 秒，這是 Apps Script 在「暖機」，免費方案避不掉。
    • 新版程式碼會在等待時顯示「輸入中」動畫，讓對方知道機器人正在回答。
    • 改完程式碼，記得「管理部署作業 → 編輯 → 新版本 → 部署」才會生效。
    機器人回覆「抱歉，AI 暫時無法回覆」

    這代表 LINE / Telegram 那一半已經通了，問題在 Gemini 這一端。後面接的訊息就是原因：常見是金鑰貼錯（多了空白），或短時間問太多次超過免費額度。到 Apps Script 執行 testGemini 就能看到詳細錯誤。

    出現「This model … is no longer available」

    Google 會定期停用舊的 Gemini 模型。新版範例程式碼已經會在模型停用時，自動改用程式碼裡 BACKUP_MODELS 列出的其他模型。如果還是出現這個錯誤：到「貼上程式碼」那一步，把「Gemini 模型名稱」換成錯誤訊息裡建議的名稱，重新複製程式碼貼上、儲存，再到「管理部署作業」部署「新版本」。

    出現「This model is currently experiencing high demand」

    這是 Google 那邊太多人同時使用 Gemini，暫時忙線，不是你的設定錯了，通常過幾分鐘就會恢復。新版範例程式碼遇到忙線，會自動改用備用模型。如果全部模型都忙線，機器人會回「Google 的 AI 現在太多人使用，請過一兩分鐘再問一次」。上課時全班同時測試特別容易遇到，可以請學員錯開幾秒再按執行。

    LINE 按下 Verify 出現錯誤

    新版範例程式碼按 Verify 應該會顯示 Success。如果顯示失敗：確認用的是本頁最新的程式碼、已經部署「新版本」、網址結尾是 /exec、存取權是「所有人」。也可以直接用手機傳一則訊息測試，機器人有回覆就代表通了。

    Telegram：/start 有回，後面的問題都沒反應

    舊版範例程式的回應方式會被 Google 轉址，Telegram 以為沒送到，就一直重送同一則訊息，後面的訊息全部卡在排隊。修法：

    • 回「貼上程式碼」那一步重新複製程式碼（新版最後一行是 HtmlService.createHtmlOutput），整份換掉、存檔。
    • 「部署 → 管理部署作業 → 編輯 → 版本：新版本 → 部署」。
    • 回「把網址告訴 Telegram」那一步，再按一次 開啟設定網址，這會順便清掉卡住的舊訊息。
    • 想確認狀況：同一步按 查看目前設定。pending_update_count 是排隊中的訊息數，正常是 0；last_error_message 出現 302 就是這個問題。
    • 還是沒反應：Apps Script 左側的 執行項目（三條線加箭頭的圖示）可以看到每次 doPost 有沒有被呼叫、有沒有失敗。
    Telegram 機器人同一個問題回了兩次以上

    舊版程式的回應會被轉址，Telegram 以為沒送到而重送。請重新複製本頁的程式碼，再部署「新版本」。新版另外用 isDuplicate 擋掉重複訊息。

    Google 跳出「這個應用程式未經 Google 驗證」

    這是你自己寫的程式，Google 沒有審核過才會這樣提示。點 進階 → 前往「專案名稱」（不安全） → 允許 即可。只授權給你自己的 Google 帳號。

    金鑰外洩了怎麼辦？

    金鑰就像密碼，不要截圖貼到群組。外洩時：Gemini 到 AI Studio 刪除舊金鑰再建新的；LINE 在 Developers 重新 Issue 權杖；Telegram 對 BotFather 傳 /revoke。換完記得改程式碼並部署新版本。
